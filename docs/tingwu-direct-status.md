# 腕录 2.2 普通听悟账号直传验证

2026-10-23。设备为 OWW261（Android 11，466×466 圆屏），配对手机为一加 Ace 6。

## 当前使用

**手表录音 → 停止并保存 → 通过手机共享网络直接上传听悟 → 在手机听悟查看结果。** 手机不承担手动接收和导入步骤，手表不展示纪要。

1. 打开手表上的“腕录 2.2”。本机使用独立预览包 `com.zcode.watchrec.preview`，原版未卸载。
2. 首次在第三页点“支付宝扫码登录”，用支付宝扫描官方二维码并确认登录。账号 Cookie 由手表应用的 WebView 保留，不要求 API Key，也没有导出到电脑。
3. 本次已开启“结束后自动上传”，只对之后在腕录中录制并保存的新文件生效；不会批量上传现有录音。也可在文件列表选中一段录音，点“上传听悟”，再在第三页确认。
4. 上传后去手机听悟查看记录。登录过期时重新扫码。失败时原件留在手表；不确定云端是否已经接受请求时，先查询原记录，不直接新建副本。

## 实机证据

- 默认网络为已验证的蓝牙 `COMPANION_PROXY`，具有 `INTERNET`、`VALIDATED`；访问听悟首页返回 HTTP 200。没有要求用户另开热点。
- 用户通过支付宝完成官方扫码；手表原生登录检查确认账号有效。升级安装后会话仍有效，没有再次扫码。
- 使用新建的 1 秒、1,185 字节静音 AAC 文件验证真实云端上传，没有上传用户的原录音。首个样本经听悟状态接口确认 `status=0`（处理完成）。
- 验证中发现：文件确认后，云端可能已开始或完成处理；重复发起处理会收到拒绝响应。修订为先查询指定记录的状态，处理已开始时直接确认成功；对提交时的状态竞争再查询一次，不误报为上传失败。
- 最终安装包使用第二个新样本，一次点击完成上传与处理提交，没有手动重试。收到上传和处理接受回执，设备保存状态为 `done`；这不代表静音文件生成了有内容的会议纪要。
- 两个样本成功后均已清除本地缓存的临时上传链接。手表上的两段静音测试文件已删除，云端测试记录保留供核对。
- 6 段原录音共 **5,895,303 字节**，最终逐一核对 SHA-256 与本机备份一致；原版应用及备份均保留。
- 已安装 APK 的 SHA-256 与最终构建产物一致，版本为 **2.2 / versionCode 10**。
